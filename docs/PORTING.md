# PORTING — 게임 업데이트가 나오면 어떻게 옮기는가

> 실제 사례: 게임 업데이트 **v1.8.0 → v1.15.0** 이식 기록.
> 이 문서는 다음 업데이트 때 같은 절차를 반복할 수 있도록 남긴 것이다.

## 왜 그냥은 안 되는가

`번역_마스터.json` 의 좌표는 **특정 바이너리에만 유효**하다.

- `exe` 의 `off` = 그 버전 `main` 의 파일 오프셋
- `exe_ext` 의 `ents` = 그 버전 `DT_RELA` 테이블 안의 엔트리 위치
- `rdb` 의 `off` = 그 버전 CHK 본문 안의 오프셋

v1.15.0 에서 `.text` 는 +289,776B, `.rodata` 는 +109,504B, `.data` 는 +22,160B 커졌고
RELA 엔트리는 802,618 → 804,688 개가 됐다. **모든 오프셋이 어긋난다.**

## 원칙: 좌표가 아니라 내용으로 옮긴다

오프셋은 못 믿으니 **문자열 내용**을 열쇠로 쓴다. 같은 문자열이 여러 번 나오면
**"몇 번째 출현인가"** 로 구별하고, 출현 횟수가 다르면 **이웃 앵커가 만드는 창(window)** 으로 좁힌다.

### φ — 문자열 오프셋 매핑 (`tools/port/port_lib.py`)

1. 구 버전에서 마스터가 가리키는 오프셋의 문자열을 뽑는다.
2. 두 바이너리의 문자열영역을 NUL 로 쪼개 그 문자열들의 **출현 위치 목록**을 만든다.
3. 출현 횟수가 같으면 **같은 순번끼리** 대응시킨다.
4. 다르면 이미 확정된 이웃 앵커 사이 구간에 후보가 하나뿐인지 보고 확정한다.

> v1.15.0 실적: 182,787건 중 **182,767건 확정, 모호 0건, 소실 20건**(게임에서 삭제된 문자열).
> 단조성 위반 3건은 인접 문자열의 순서 교환으로 확인돼 무해.

### ψ — RELA 엔트리 매핑 (`tools/port/build_maps.py`)

RELA 테이블을 **시퀀스**로 보고 patience diff 한다.

1. 각 엔트리의 토큰 = `addend` 가 가리키는 **문자열 내용**(버전 무관한 값).
2. 양쪽에서 딱 한 번 나오는 토큰 = 앵커 → **LIS** 로 단조 앵커만 남긴다.
3. 앵커 사이 구간은 `SequenceMatcher` 로 채운다.

> v1.15.0 실적: 802,618 중 **779,192 매핑, 단조성 위반 0**.
> `exe_ext` 의 ents 22,485개 중 22,484개가 매핑됐고, **문장 5,269개 중 5,243개**가
> 24바이트 연속성까지 유지한 채 이식됐다(나머지는 게임 쪽 구조가 바뀐 것).

### 검증이 핵심이다

이식한 오프셋마다 **그 자리에 정말 같은 원문이 있는지** 바이트 비교로 확인한다
(`tools/port/port_master.py`). v1.15.0 에서는 내용 불일치 **0건**이었다.
여기서 하나라도 어긋나면 [HISTORY §0](HISTORY.md#0-버전-혼합--잘못된-소스에서-추출한-베이스)
의 버전 혼합 사고가 재현된다.

## 부트스트랩을 없앤 이유

v1.4 까지는 `bootstrap/main-safe28.xdelta`(3.2MB)가 필요했다. safe28 에는 마스터로
설명되지 않는 것이 두 가지 들어 있었기 때문이다.

| 잔여물 | 규모 | 정체 |
|---|---|---|
| RELA addend 재작성 | 67,391곳 | 죽은 zero-run 풀 리다이렉트 ([HISTORY §4](HISTORY.md)) |
| 풀에 기록된 문자열 | 1.27MB | **잘리지 않은 전체 한국어 문장** |

이 문장들은 마스터에 없었다(마스터의 `ko` 는 제자리에 들어간 **잘린** 사본이다).
그래서 safe28 에서 `(원문 → 전체 문장)` 쌍을 역추출해 마스터의 새 섹션
**`exe_pool`(34,575건)** 으로 올렸다(`tools/port/extract_pool.py`).

이제 `tools/BUILD_BASE.py` 가 원본 + 마스터만으로 풀을 다시 찾고 문장을 기록하고
포인터를 바꾼다 — **결정적이고, 부트스트랩 바이너리가 필요 없다.**

> ⚠ 풀 **좌표**를 옮기려는 시도는 실패했다. 풀 런 795개 중 문맥 64바이트로 유일하게
> 대응되는 것은 244개뿐이었다(나머지는 같은 크기 1687B 구멍이 반복되는 구조라 문맥이 겹침).
> **좌표를 옮기지 말고 알고리즘을 다시 돌려라** — 풀 탐색은 구조 기반이라 버전이 달라도 재현된다.

## RDB 는 훨씬 쉽다

v1.15.0 에서 **`RES00.RDB`(6.6GB)는 원본이 바이트 단위로 동일**했다. 바뀐 것은
`RES10.RDB` 와 `RES00.RDI`(항목 15,543 → 15,564) 뿐.

1. RDI 를 비교해 **레코드가 바뀐 파일**만 추린다 (v1.15.0: 808개).
2. 마스터가 건드리는 431개 파일과 교집합을 내고, **CHK 본문 md5** 를 실제로 비교한다.
   → v1.15.0 에서 실제로 내용이 바뀐 것은 **7개**(`SEN_*_2ND`, 2025→2026 로스터)뿐이었다.
3. 그 7개만 **사전 기반**으로 다시 매핑한다 — 선수명은 위치가 아니라 이름이 열쇠다.
   `(원문 → 번역)` 사전을 구 마스터 전체에서 만들고 새 본문의 모든 문자열에 적용한다
   (`tools/port/rdb_port.py`).
4. 사전에 없는 것 = **신규 선수/소개문** → 번역 대상 목록.

## 신규 문자열 찾기 (절대 스캔)

diff 기반으로는 못 찾는다. 새 바이너리의 문자열영역 전체를 훑어
**마스터가 커버하지 않으면서 가나/한자를 포함한 문자열**을 뽑는다
(`tools/port/scan_new.py`).

> v1.15.0 실적: exe 신규 **51건**(가나 45 + 순한자 6), 기존 미번역 잔존 231건.
> RDB 신규 **606건**(2026 로스터 선수명 547 + 소개문 59).
> 순한자·전각만 있는 후보 6,564건은 바이너리 오탐 위험이 커 손대지 않았다
> ([HISTORY §3](HISTORY.md) 참고).

## 폰트 — 파일이 바뀔 수 있다

v1.15.0 에서 **`COMMON_2D_ADD.CHK` 가 삭제되고 `COMMON_2D_2ND.CHK` 가 생겼다.**
`COMMON_2D.CHK` 는 바이트 동일이라 기존 한글 폰트가 그대로 쓰였지만, 2ND 는 새로 만들어야 했다.

- 2ND 는 COMMON_2D 와 같은 UNCDFONT 구조(FNTL 56×56 / FNTS 44×44)에 한자 27자가 추가된 것.
- `tools/BUILD_FONT_2ND.py` 가 한글 COMMON_2D 의 tsv 대상 셀 글리프를 같은 코드포인트에 복사한다
  (메트릭 동반, 글리프 데이터 델타 FNTL −6 / FNTS 0).
- 결과를 잔차 팩에 `runs` 로 넣고 없어진 ADD 항목은 뺀다 (`tools/BUILD_RESIDUAL.py`).

> **폰트를 빠뜨리면 증상이 조용하다** — 번역은 들어갔는데 화면에는 "깨진 한글"이 뜬다.
> 로스터 화면이 어느 폰트로 렌더되는지 반드시 확인할 것
> ([HISTORY §1](HISTORY.md) 의 ADD 폰트 사고).

## 절차 요약

```bash
# 0) 두 버전 원본을 나란히 둔다
# 1) 좌표 매핑
python tools/port/build_maps.py         # φ, ψ 생성 (캐시)
python tools/port/port_master.py        # exe / exe_ext 재좌표화 + 내용 검증
python tools/port/extract_pool.py       # 구 베이스에서 exe_pool 역추출(최초 1회)
python tools/port/rdb_port.py           # 바뀐 CHK 만 사전 기반 재매핑
python tools/port/scan_new.py           # 신규 문자열 수색 → 번역
# 2) 폰트·잔차
python tools/BUILD_FONT_2ND.py ...
python tools/BUILD_RESIDUAL.py ...
# 3) 빌드·검증
python tools/SETUP_WORKSPACE.py <ws> --orig <새 덤프> --link
set PAWA_ROOT=<ws>
python tools/BUILD_EXE.py
python tools/BUILD_RDB_FROM_MASTER.py --fresh
python tools/VERIFY_EXE.py <원본main> <빌드main> <마스터> <tsv>
python tools/VERIFY_RDB.py <repack_out> <마스터> <tsv>
```

## 체크리스트

- [ ] 새 원본 4파일 MD5 를 `SETUP_WORKSPACE.py` 에 갱신했는가
- [ ] φ/ψ 이식 후 **내용 불일치 0** 인가 (아니면 중단)
- [ ] 삭제된 CHK / 새로 생긴 CHK 를 확인했는가 (특히 **폰트**)
- [ ] 신규 문자열을 절대 스캔으로 찾아 번역했는가
- [ ] `BUILD_EXE` 의 3단계 assert 가 전부 통과했는가
- [ ] `VERIFY_RDB` 에서 슬롯 무결성 실패 0 인가
- [ ] 빌드가 **결정적**인가 (두 번 돌려 같은 md5)
- [ ] 실기/에뮬에서 **장기 진행(마이라이프 28일차 이상)** 을 테스트했는가
