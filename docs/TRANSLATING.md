## 파일 구조

```jsonc
{
  "meta": { ... },
  "exe": [                    // 실행파일 안의 문자열 (182,787개)
    { "off": 66856190,        //   파일 오프셋 — 절대 고치지 마세요
      "jp": "ドラフト選手として…",  //   일본어 원문(참고용, 고치지 마세요)
      "ko": "드래프트 선수로서…",   //   ★ 여기만 고칩니다
      "maxb": 110 }           //   쓸 수 있는 최대 바이트(원문+남는 공간)
  ],
  "exe_ext": [                // 마이라이프 완성 문장 (5,269개)
    { "ko": "오늘은 기다리고 기다리던 입단 기자회견.",
      "ents": [45492313, ...] }   // 이 문장이 대신할 조각 슬롯들 — 고치지 마세요
  ],
  "rdb": [                    // RDB 안의 문자열 (54,510개)
    { "file": "ARENA_MAIN.CHK",
      "off": 8696, "jp": "過去の競技", "ko": "과거대회", "maxb": 15 }
  ]
}
```

**`ko` 외의 필드는 건드리지 마세요.** `off`/`ents`는 게임 파일 안의 위치라서 바꾸면 엉뚱한 곳이
덮어써집니다.

한글은 그냥 한글로 적으면 됩니다. 빌드할 때 `hangul_to_hanja.tsv`를 통해 한자 글리프 자리로
자동 인코딩됩니다(폰트가 그 자리에 한글 모양을 갖고 있습니다).

## 고칠 때 지켜야 할 규칙

### 1. 바이트 예산 (`maxb`)

문자열은 **제자리에** 써 넣기 때문에 원래 자리보다 커질 수 없습니다.
한글 1자 = 3바이트, ASCII 1자 = 1바이트로 계산합니다.

```python
len(''.join(TSV.get(c, c) for c in ko).encode('utf-8')) <= maxb
```

넘으면 빌드가 알아서 잘라내지만(UTF-8 경계까지), 문장이 중간에 끊기므로 **미리 줄이는 편이
낫습니다**. `exe_ext`는 예산이 더 빡빡합니다(아래 참고).

### 2. 줄 규칙 — 한 줄 24자, 대사창 3줄

게임은 **전각 24자**에서 자동 줄바꿈하고, 대사창은 **3줄(=72자)**까지 보여 줍니다.
번역이 원문보다 길어 줄 수가 늘면 글자가 잘리거나 다음 대사로 밀립니다.

- 전각(한글·한자·가나) 1.0 / 반각(ASCII) 0.5로 폭을 셉니다
- `\n`이 들어 있으면 각 줄이 24 이하인지 확인
- `\n`이 없으면 전체 폭이 원문 폭을 넘지 않게 (원문과 같은 줄 수를 유지)

위반 항목을 찾아 주는 도구가 있습니다: `tools/SCAN_RDB_LINE.py`

### 3. 서식 지정자와 제어문자 보존

`%s` `%d` 같은 서식 지정자는 게임이 선수 이름·숫자를 채워 넣는 자리입니다.
**개수와 순서를 원문과 똑같이** 유지하세요. 빠뜨리거나 늘리면 엉뚱한 값이 표시되거나
게임이 죽을 수 있습니다.

```
원문: %sが%d回参考完全試合の快投      ← %s 1개, %d 1개
번역: %s가 %d회째 참고 기록 완봉의 쾌투   ← 그대로 유지 ✓
```

원문에 있는 제어문자(색상 태그 등)도 그대로 두세요.

### 4. 조사 처리

`%s` 뒤에는 어떤 이름이 올지 알 수 없어 받침을 확정할 수 없습니다.
이럴 때는 `이(가)` 처럼 병기하는 것이 관례입니다. 앞 글자가 고정된 한글이면
`tools/FIX_JOSA.py`가 받침에 맞춰 자동으로 확정해 줍니다.

### 5. `exe_ext`(마이라이프 완성 문장)의 특수 규칙

이 문장들은 원본 조각 슬롯 자리에 나눠 담깁니다. 그래서 **조각 수만큼만 분할**할 수 있고,
조각이 2개뿐인데 문장이 길면 들어갈 자리가 없습니다.

- 빌드 로그의 `스킵 N`이 그런 경우입니다. 스킵되면 **그 문장은 반영되지 않고** 예전 표시가 남습니다
- 스킵이 생기면 그 문장을 더 짧게 고치세요 (현재 배포본은 스킵 0)
- 여러 조각으로 나뉘어도 게임이 순서대로 이어붙이므로 표시는 한 문장으로 보입니다

## 수정 → 빌드 → 확인

```bash
# 0) 작업공간이 준비되어 있어야 합니다 (docs/BUILD.md 1단계)
set PAWA_ROOT=D:\pawa_ws

# 1) data/번역_마스터.json 을 고칩니다 (아래 예시 참고)
#    고친 파일을 작업공간에도 복사하세요
copy data\번역_마스터.json %PAWA_ROOT%\번역_마스터.json

# 2) 빌드
python tools/BUILD_FROM_MASTER.py          # 실행파일
python tools/BUILD_RDB_FROM_MASTER.py      # RDB (텍스트만 고쳤다면 생략 가능)

# 3) 확인
python tools/VERIFY_BUILD.py               # 고쳤으니 MD5는 달라집니다(정상)
```

빌드 스크립트가 스스로 검증하므로, **`assert`로 멈추면 뭔가 잘못된 것**입니다.
로그의 `스킵`, `trunc` 같은 숫자도 확인하세요.

## 대량 수정 예시

```python
# -*- coding: utf-8 -*-
import json
p = 'data/번역_마스터.json'
m = json.load(open(p, encoding='utf-8'))

n = 0
for r in m['rdb']:
    if r['ko'] == '과거대회':
        r['ko'] = '지난 대회'; n += 1
for r in m['exe']:
    r['ko'] = r['ko'].replace('컨디숀', '컨디션')

json.dump(m, open(p, 'w', encoding='utf-8'), ensure_ascii=False)
print('수정', n)
```

> `ensure_ascii=False`를 빠뜨리면 파일이 몇 배로 커집니다. `indent`는 넣지 마세요(용량).

바이트 예산을 미리 검사하려면:

```python
TSV = {}
for ln in open('data/hangul_to_hanja.tsv', encoding='utf-8-sig'):
    x = ln.rstrip('\n').split('\t')
    if len(x) >= 2 and x[0] and x[1]: TSV[x[0]] = x[1][0]
enc = lambda s: ''.join(TSV.get(c, c) for c in s).encode('utf-8')

over = [r for r in m['rdb'] if len(enc(r['ko'])) > r['maxb']]
print('예산 초과:', len(over))
```

## 자주 하는 실수

| 증상 | 원인 |
|---|---|
| 문장이 중간에 잘림 | `maxb` 초과 — 더 짧게 고치세요 |
| 대사가 다음 줄로 밀리거나 사라짐 | 줄 규칙(24자/3줄) 위반 |
| 이름 자리에 이상한 값이 뜸 / 게임이 죽음 | `%s`·`%d` 개수나 순서를 바꿨음 |
| 글자가 네모로 보임 | `hangul_to_hanja.tsv`에 없는 문자를 씀(특수문자·한자) |
| 고쳤는데 게임에 반영이 안 됨 | 작업공간에 복사하지 않았거나, MOD 폴더에 결과물을 안 넣었음 |
| 마이라이프 대사만 안 바뀜 | `exe_ext` 수납 스킵 — 빌드 로그의 `스킵` 수 확인 |
